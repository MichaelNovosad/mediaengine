# MediaEngine acceptance criteria

Tick a box only with evidence (test name, log, screenshot path, or a device result from the owner).
Tags: `[auto]` automated test or script, `[sim]` simulator, `[device]` real hardware by the owner, `[lawyer]` needs legal review, `[manual]` judgement.
Milestones: E0 build system and license skeleton · E1 probe, I/O and core Swift types · E2 remux to AVPlayer (the first MKV plays) · E3 subtitles and tracks · E4 software decode, renderer, PiP · E5 packaging, docs, sample app, distribution rehearsal · E6 1.0 release pack.
**Gate: PlayerApp starts after E3.** E4 and E5 run alongside the app's early milestones.

## Definition of done (every milestone)

- [ ] `scripts/verify.sh` passes: package builds and tests for iOS, iPadOS (simulator), macOS and visionOS (simulator) with zero warnings. `[auto]`
- [ ] License check passes (no GPL, no nonfree; see LIC-1). `[auto]`
- [ ] Public API is documented; DocC builds without warnings. `[auto]`
- [ ] Fixture corpus tests pass; nothing crashes under the sanitizers. `[auto]`

## API: a Swift-friendly interface

Quick start, required to work exactly like this (E2):

```swift
import MediaEngine

let session = try await PlaybackSession(url: fileURL)   // probes and chooses the best path
let item = try await session.makePlayerItem()            // plain AVPlayerItem
player.replaceCurrentItem(with: item)                    // AVPlayerViewController / VideoPlayer
```

- [x] API-1 The quick start above works with an MKV file in the sample app on iOS, macOS and visionOS, with no other setup (no bridging header, build phase, manual embed or framework search path). `[auto]` (E2) **Progress (2026-10-24):** The three-line quick start works on macOS in `PlaybackSessionTests`; sample apps on iOS/visionOS come in E5. `makePlayerItem()` is `@MainActor` because `AVPlayerItem` is main-actor isolated in the 27 SDK. **Evidence (2026-10-26):** `Samples/QuickStart` is a complete SwiftUI app around the quick start and `Samples/Player` a fuller one; both build for macOS, an iOS simulator and a visionOS simulator with nothing but the package dependency (`scripts/check-samples.sh`, part of `scripts/verify.sh`), and `QuickStartTests` runs the quick start line for line (open an MKV, make the item, hand it to an `AVPlayer`, let AVFoundation read duration and the subtitle menu) on macOS and on the iPhone, iPad, iPhone Duo and visionOS simulators. On a real device it is untested (AirPlay, PiP and phone playback are `[device]`).
- [x] API-2 Public API exposes no C types, raw pointers or FFmpeg identifiers; it uses Foundation, AVFoundation, CoreMedia and CoreGraphics types and `Locale.Language` for languages. `[auto]` (E1) **Evidence (2026-10-24):** `internal import FFmpegLGPL` everywhere; `scripts/check-public-api.sh` fails on public imports or FFmpeg types in public declarations; public model uses Foundation types and `Locale.Language`.
- [x] API-3 Swift 6 strict concurrency: public types are `Sendable` where sensible, sessions are actors or `@MainActor`, ThreadSanitizer is clean. `[auto]` (E1) **Evidence (2026-10-24):** Swift 6 mode; `swift test --sanitize=thread` passes all 46 tests (no data races).
- [x] API-4 `async`/`await` and `AsyncSequence` first; operations are cancellable and stop within 100 ms of cancellation. `[auto]` (E1) **Evidence (2026-10-24):** Tests `cancelledBeforeStart`, `cancelledDuringReads` (stops in under 500 ms) and the HTTP `cancellation` test.
- [x] API-5 One typed `MediaError` with stable cases, a plain-language `errorDescription` safe to show users and a technical `debugDescription`. (E1) **Evidence (2026-10-24):** `MediaError` with plain-language `errorDescription` (test `errorDescriptions`: no paths) and `debugDescription`.
- [x] API-6 State is `@Observable` where a UI needs it. `MediaVideoView` wraps the software renderer for SwiftUI, UIKit and AppKit. (E4) **Evidence (2026-10-26):** `PlaybackController` is `Observable`; `AVPlayerController` and `SoftwareController` are `@Observable`; `MediaVideoView` (SwiftUI) and `MediaVideoLayerHost` (UIKit, AppKit) show their pictures. Built for iOS, macOS and visionOS by `scripts/verify.sh`; no view test on a screen (`[sim]`).
- [x] API-7 A shared `PlaybackController` protocol (play, pause, seek, rate, current time stream, track selection) is implemented by both the AVPlayer path and the software path so apps can switch paths without changing UI code. (E4) **Evidence (2026-10-26):** `PlaybackController` (play, pause, rate, seek, `timeUpdates`, track selection, subtitle frames) implemented by both controllers; `PlaybackSession.makeController()`; `SoftwareControllerPlaybackTests` run the same calls against both.

Compile-time switching is proven (E0); swapping binaries needs the plug-in design in D-E11. (E4) **Progress (2026-10-26):** the binary swap is done by variants (D-E11), traits keep switching code; `Package.swift` picks the variant with `MEDIAENGINE_PROFILE`. **Evidence (2026-10-26):** `scripts/check-traits.sh` builds and tests every trait combination; the optional binaries are variants chosen by the package manifest (`MEDIAENGINE_PROFILE`), so an app that does not need the extended variant links none of its code (core 2.9 MB against extended 5.8 MB).

## RMX: remux to AVPlayer

- [ ] RMX-1 `makePlayerItem()` plays MKV/WebM with H.264, HEVC (including HDR10 and HLG, and Dolby Vision 5 and 8 once RMX-11 is cleared) and hardware-decodable AV1, with AAC, AC-3, E-AC-3 (Atmos preserved), ALAC, FLAC, Opus and MP3 audio, inside `AVPlayerViewController` and `AVPlayerView`, with the system controls. `[sim]` `[device]` (E2) **Progress (2026-10-24):** Verified with AVPlayer on macOS for H.264, HEVC Main and HEVC Main 10 HLG with AAC, AC-3 and E-AC-3 passthrough (play, seek, finish). **Open:** HDR10/PQ is rejected by AVPlayer's HLS path (see PROGRESS.md); FLAC/Opus wait for the E2.4 transcode; iOS/visionOS playback is not yet exercised on simulators.
- [ ] RMX-2 Audio AVPlayer cannot decode (FLAC, PCM, Vorbis, Opus, and with `LicensedAudio` DTS and TrueHD) is decoded by the engine and re-encoded to lossless ALAC (no AAC: its encoder delay would glitch every segment boundary), keeping up to 7.1 channels. (E2, E4) **Progress (2026-10-24):** FLAC and PCM are bit-exact (up to 24-bit, any sample rate). Opus and Vorbis are transcoded with decoder pre-roll at segment starts (Opus 0.5 s, Vorbis 0.2 s): a segment transcoded alone equals the same stretch of a whole-file transcode for Vorbis (0 of 528,384 samples differ) and to within rounding noise for Opus (274 of 576,000 differ, worst step -138 dBFS); without pre-roll the test sees a difference (`AudioTranscodeTests.prerollSegments`). DTS/TrueHD wait for the licensed module; multichannel (5.1/7.1) layouts are untested.
- [x] RMX-3 All audio tracks appear in the system audio menu as `AVMediaSelectionOption`s (HLS alternate renditions); only the selected one is processed. (E2, E3) **Evidence (2026-10-25):** AVPlayer lists every track and switching to the transcoded FLAC track plays (`audioSelection`); transcoding is lazy (`lazyTranscoding`). The system menu shows only the language name, so tracks of one language look alike there; `PlaybackSession.audioChoices` / `select(_:on:)` give hosts unique names and selection (`TrackChoiceTests`, `TrackSelectionTests.sameLanguage` with two English tracks and a duplicate title; RESEARCH.md sections 17 and 20).
- [ ] RMX-4 Text subtitle tracks (SRT, ASS/SSA, WebVTT, tx3g) appear in the system subtitle menu as WebVTT renditions. ASS styling is reduced to what WebVTT can express; full styling uses the overlay path (SUB-2). (E3) **Progress (2026-10-25):** SubRip and ASS tracks of MKV files appear as WebVTT renditions; AVPlayer delivers their cues in step with the video, with ASS alignment and `\pos` placement (`SubtitleTextTests`, `SubtitlePlacementTests`, `SubtitleRenditionTests`, `AVPlayerEndToEndTests.subtitleCues` and `subtitlePlacement`); cues are read from the windows that are built anyway, with a 15 s look-back, in any request order (`spanning`, `orderDoesNotMatter`, `readsOnlyNearbyWindows`; RESEARCH.md section 18). **Open:** WebVTT settings from block additions, forced/hearing-impaired flags on real files, tx3g sources.
- [ ] RMX-5 Seeking works to any position through the index; resume after seek within 500 ms on local files; files with a missing or broken index fall back to a scan. (E2) **Progress (2026-10-24):** Segments are built independently and in any order (AVPlayer seeks back and forward in `AVPlayerEndToEndTests`). Measured on an M1 Max with `BenchmarkTests`: AVPlayer resumes playing 242 ms (3 h file) and 393 ms (1080p, 13 Mbps) after a seek, median of 8 with zero tolerance; building a video segment takes under 5 ms, a transcoded FLAC segment 17 ms; 1365-segment index opens in 4 ms. The scan fallback for a missing index is covered by `KeyframeIndexTests`; phone numbers are open.
- [ ] RMX-6 Time to first frame at most 1.5 s on a physical iPhone for a local 5 GB file (initial target, calibrate after E-S3). `[device]` (E2) **Progress (2026-10-24):** AVPlayer starts playing after 464-541 ms on an M1 Max (526 MB and 281 MB files; open and first segments take 6-26 ms of that). A 5 GB file on a phone is still to be measured.
- [x] RMX-7 Memory stays under a fixed budget (initial target 150 MB) during playback of any file; segment generation is on demand with bounded lookahead. `[auto]` (E2) **Evidence (2026-10-25):** segments are cut by time and by size (cap 24 MB, `SegmentPlanTests`, `sizeCap`) and finished fragments live in `mmap`ed pages that return to the system on release (`BigBufferTests`, `ExclusiveTests.fragmentsAreReturned`, `fragmentsDoNotAccumulate`); segment cache budget 48 MB. Measured with `BenchmarkTests` (M1 Max): peak growth 82 MB for 1080p at 13 Mbps, 101 MB for 4K at 44 Mbps, 116 MB for 4K at 66 Mbps, 65 MB for a 3-hour low-bitrate file (RESEARCH.md section 15). **Limits:** a single GOP above the 24 MB cap is not split, so a file with multi-second GOPs at 100 Mbps would exceed 150 MB; phone numbers are open.
- [x] RMX-8 Chapters (titles, times, kinds) and the title and cover art are available to the host: chapters through `MediaInfo.chapters` and `Chapter.kind` (the system player takes no chapter markers from an app on iOS, macOS or visionOS), title and cover through `AVPlayerItem.externalMetadata` on iOS and visionOS. (E3) **Evidence (2026-10-25):** `ChapterTests`, `AttachmentTests`, `PlayerItemMetadataTests` (the item test runs on the iPhone simulator); RESEARCH.md section 19. **Open `[device]`:** how Now Playing and the lock screen show the title and cover; macOS has no `externalMetadata`, the app sets `MPNowPlayingInfoCenter` from `info` and `MediaSource.data(of:)`.
- [x] RMX-9 Transport: `.loopbackServer` (the only one; `.lanServer` is added only if E-S4 proves AirPlay needs it). The server binds to loopback, uses a random port and an unguessable per-session path, serves only the open session and stops when the session ends. `[auto]` (E2) **Evidence (2026-10-25):** `LoopbackServerTests`: loopback interface only (every external address tried), system-chosen port, 128-bit token per server, Host-header check, GET/HEAD only, path tricks rejected, stops with the session. - [ ] RMX-10 AirPlay behavior per transport is recorded (E-S4), including whether the server must bind to the network interface while AirPlaying and exposed as `session.airPlaySupport` so the host UI can react. `[device]` (E2)
- [ ] RMX-11 Dolby Vision signaling is correct for profiles 5 and 8; profile 7 is converted to 8.1 when the `DolbyVision` trait is on, otherwise falls back to the HDR10 base layer. Visible in `playbackPlan`. - [x] RMX-13 Truncated or damaged files play what they can and never crash. `[auto]` (E2) **Evidence (2026-10-24):** `DamagedFileTests`: 756 deterministic mutations per run (truncation, header and random corruption, zeroed ranges) of four fixtures pass through the whole remux path without a crash or hang, clean under ASan with an instrumented FFmpeg; a source that fails after opening reports an error; `AVPlayerEndToEndTests.truncatedDownload`: a file cut at 60% plays up to its last complete data and stops without an error.
